# Menu text roles

Essential menu headings and labels use the shared body role, and accelerator captions use the label role. Changing the text preference scales both roles. Check marks, radio marks, disclosure marks and other optical symbols retain their existing sizes. Row height increases to fit the body role. Both built-in and exported menu width calculations use the current shaped font metrics; available output width remains a hard bound for built-in menus.

`tests/desktop/menu_typography_qml.py` paints the production exported `MenuCard` in a fully detached private software-renderer namespace. Sixteen cases cover light and dark palettes, 100/115/130/150 percent text, and 380/700 pixel hosts. It requires the actual public font, expected role sizes, nonoverlapping label and accelerator rectangles, row containment, untruncated sample captions, visible text ink and warning-free completion. The sample row includes a disabled action and a checked action, but these are not separate semantic-state assertions.

The renderer host supplies inert captured state and a fixed 350 pixel menu capacity. This test does not prove real exported-provider discovery, dynamic `GlobalMenu.widthFor`, built-in heading placement, pointer routing, keyboard behavior, submenu placement or arbitrary long translations. `tests/desktop/menu_scaled_native.py` supplies a separate bounded native acceptance corpus: seven checks per compositor at 150 percent verify actual 20 pixel built-in/exported labels and 18 pixel accelerators, native heading traversal, exact same-process exported provider identity, generation cancellation, nested arrows/Escape, 640 pixel output overflow containment, exact captured command dispatch and restored client input. All child logs are checked after reaping. The full older stale accessibility/pointer corpus remains separate. The enlarged-text fixture explicitly supplies unavailable optional hardware state, private null audio, a private GTK client and a stable complete supported US map within X11 keycode bounds. Its keymap is opt-in; the ordinary physical helper default is unchanged. No private desktop state or hardware is mounted. No reference-system measurements or full visual parity are claimed.
