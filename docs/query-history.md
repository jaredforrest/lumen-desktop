# Deliberate query history

Query history is opt-in user data, separate from clipboard history. The launcher records a nonempty ordinary query on dismissal, excludes Clipboard-category queries, and recalls recent queries with Alt+Up/Down while restoring the draft on returning past the newest entry. The private store retains at most 20 distinct queries of at most 512 characters. Files are owner-only, with an owner-only parent directory.

Every record intent captures the opaque generation obtained from the history service. Clear rotates that generation under the same lock before removing the plaintext query file; a delayed record from an earlier generation is rejected without replay or retry. A request observing disabled policy also rotates the generation and deletes history. The owned UI captures a disable transition as a queued Clear even if policy is reenabled before that request executes. External policy transitions that no running client observes cannot be inferred from a later enabled snapshot. No generation is invented for a record when the initial list has not completed. Generation metadata contains no query text and survives restarts so queued old processes cannot recreate cleared history.

The installed native fixture uses private homes, buses, compositor input, synthetic queries and an argument-only fallback observer. It exercises the actual installed launcher/router, stale PID fallback, shell replacement, recall draft/bounds, excluded clipboard-category queries, and the actual Settings Clear action with a held original record. Source-hashed adapters isolate service PID lookup and unrelated system/account probes; query/record logic is unchanged.
