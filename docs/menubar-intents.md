# Built-in menu intent and accessibility

Built-in menu rows expose menu-item semantics, names, enabled state and selected state. Separators and unavailable commands remain non-actionable. Down/Up and Tab/Backtab traverse enabled rows; Home/End select the first/last enabled row. Return or Space activates the captured selection. Escape dismisses the popup and releases its exclusive keyboard surface. Model replacement clears keyboard selection and restores popup focus; Return never rereads a replacement at the old numeric index.

Opening a menu captures its original window and owned Files main-window context. Pointer press, keyboard selection and assistive activation produce an intent containing the actual row, menu session, exact live toplevel object, application identity and any captured close-all window set. Dispatch validates the intent against the current enabled row and live objects. Window disappearance, changed Files main context/focus epoch, dismissal or a different menu cancels stale authority. Close All only closes the originally captured live objects. Shared-host windows require existing explicit owned application associations; the application ID string alone does not group Files with Settings. Unknown shared-host groups disable Close All. Captured association records and their application/main/window identities must still match at release; replacing their epoch cancels the held command. A later window with the same application name or title is never substituted. Hidden built-in menus reject actions; no global key shortcut is installed by this implementation.

Owned Files actions continue through the existing Files dispatcher and its delayed focus-epoch check. Exported application menus continue through the existing D-Bus menu path; this change does not invent unsupported application commands or alter exported menu transport.

`tests/desktop/menu-native-rust` uses installed production shell components in a disposable native compositor and private accessibility/D-Bus session. Only the session-action entry point is replaced with a fixture recorder; focus and Files entry points also record dispatch while retaining their production behavior. The actual Settings window remains a bystander while its settings provider is held inactive in the fixture. The actual installed bridge runs enabled, imports the packaged shared window-context/protocol modules and watches native focus before each menu opens. Shared modules are installed from their single runtime source, rather than maintaining private copies. Native synthetic client windows test keyboard and held-pointer target replacement, source destruction and same-application replacement, removed keyboard rows, stale assistive object references, exact fresh focus/close actions, separators and disabled rows, pointer and assistive session requests, Escape and actual private Files view actions. CI runs both compositor variants, selecting software GLES for effects, and retains its logs and accessible tree. The previous implementation demonstrably closes the bystander window in the mutable-selection baseline.

This covers the built-in menu path. It does not claim complete application-exported menu coverage, application command discovery, or a new global menu keyboard shortcut.
