# Native all-desktop placement consumers

Structural workspace/output ownership remains the authority for persistent window placement, restore, desktop occupancy, removal and migration. Presentation is observed separately through native `lumen_all_desktops` version 1 metadata. A projected window is never duplicated in an inventory and retains its original container, process and foreign-surface identities.

The shared window-policy parser requires canonical bounded decimal-string revisions (u64 including zero), positive decimal-string IDs, bounded names, exact typed fields, same-output placement and consistent projected state. Missing metadata preserves compatibility with structural placement. Valid disabled metadata uses structural placement. Present malformed, unsupported enabled or unknown-version metadata refuses effective scoped activation instead of falling back to structural authority. Native saved captures retain their existing four/six identity fields.

Application selection compares effective presentation workspace, including the focused source and modal redirected target. Scratch restoration continues using its original structural restore workspace. The preview inventory digest includes validated projection metadata. Native projection changes and ordinary workspace/output events refresh observations and invalidate old scope witnesses; these events do not manufacture application-focus history. The existing whole-tree atomic guard already retains projection fields and revisions.

Window Overview preserves structural workspace/output fields for actions and occupancy. Separate effective placement fields supply the current-desktop label and all-desktop badge; invalid placement is shown as unavailable. Geometry fitting resolves the exact effective workspace ID/name while saved restoration fingerprints remain structural. Automatic fitting refuses differing structural/effective work-area rectangles because generic native centering has no verified effective-placement contract.

Pure tests cover parser refusal, disabled/absent compatibility, effective application/native selection, origin scratch restoration, projection-revision topology invalidation, observer invalidation and event classification, plus effective geometry lookup with structural saved-area identity. Native rendering, pointer routing and all-desktop placement actuation require the compositor provider's independent acceptance; these consumer tests do not claim that acceptance.
