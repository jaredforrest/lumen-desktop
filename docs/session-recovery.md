# Shell recovery

The shell is a compositor client. Ordinary applications run independently. The user service restarts a failed shell after two seconds, with at most three starts within sixty seconds. After repeated failures, an independent recovery terminal explains how to inspect logs and manually retry the shell. It does not stop applications or restart the graphical session. The terminal service has no automatic restart and only opens when the shell reports `start-limit-hit`.

Consumers can disable the automatic terminal with `services.lumen-desktop.integrations.shellRecovery.enableFallback = false` while retaining the restart bound. `fallbackPackage` may supply a different package exposing `bin/lumen-session-recovery`.

`session_shell_recovery_native.py` starts two actual GTK text documents, enters synthetic unsaved text with physical keyboard events, then kills the actual shell with SIGKILL while a menu and then the Dock hold keyboard input. Each restart must expose a working menu within five seconds after the explicit supervisor start. Both client process identities, compositor container identities and modified text remain; exactly two client windows are reported. Real input must work during the outage and after the recovered menu and Dock dismiss. The fixture supplies private audio and explicit unavailable unrelated hardware producers in a detached namespace. All child logs are checked after reaping.

The native fixture explicitly starts the replacement process; it does not run a systemd user manager. Separate Nix boundary checks verify the service restart bounds and optional fallback wiring. `session_recovery_fallback.py` executes the built recovery script with only the read-only status command and terminal executable replaced by inert private endpoints. Its three cases verify no terminal for a healthy or ordinary failure status, exactly one terminal for an exhausted restart limit, and printed manual instructions without executing a retry command. It does not claim to open a real terminal or prove systemd's own retry implementation.
